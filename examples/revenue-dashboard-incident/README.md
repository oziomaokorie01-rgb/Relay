# Revenue Dashboard Incident Example

This example shows a complete Relay investigation from DataHub context through verified organizational memory.

## Scenario

The Revenue Dashboard suddenly under-reports revenue by 35%.

Relay investigates the incident using DataHub-style metadata context, including:

- asset metadata
- ownership
- lineage
- schema information
- affected downstream assets

## Investigation Flow

1. **DataHub context**
   - Relay receives metadata for the Revenue Dashboard and its upstream lineage.
   - A schema change is detected on `raw_orders.customer_id`.

2. **Investigator Agent**
   - Identifies that `customer_id` changed from integer to string.
   - Connects the schema change to the downstream join failure.
   - Produces a root-cause hypothesis supported by lineage evidence.

3. **Repair Agent**
   - Generates a safe normalization strategy.
   - Uses `try_cast` rather than blindly forcing values.
   - Separates invalid customer IDs for monitoring.

4. **Reviewer Agent**
   - Checks whether the root cause is supported.
   - Verifies the repair against the evidence.
   - Evaluates downstream risk.
   - Recommends human approval.

5. **Human Approval**
   - A human reviewer approves the proposed resolution.

6. **Archivist Agent**
   - Converts the verified investigation into reusable organizational memory.

7. **Memory Reuse**
   - A later investigation with a similar schema mismatch can reuse the verified repair pattern instead of repeating root-cause discovery.

## Files

- `01-datahub-context.json`
  - DataHub-style asset, lineage, ownership, and schema-change context.

- `02-investigation-result.json`
  - Root cause, evidence, confidence, and agent trace.

- `03-repair-proposal.sql`
  - Example repair artifact generated by Relay.

- `04-review-and-approval.json`
  - Reviewer checks and human approval.

- `05-archived-memory.json`
  - Verified memory and an example of future reuse.

## Why This Matters

Relay is designed around a simple idea:

> Every verified investigation should make the next investigation easier.

Instead of allowing operational knowledge to disappear after an incident is resolved, Relay converts approved investigation results into reusable organizational memory for future humans and AI agents.

## DataHub Integration

Relay uses a provider abstraction for DataHub context.

The hosted demo currently supports deterministic DataHub-compatible fixtures for reliable judging.

The repository also contains a configurable GraphQL DataHub gateway for connecting Relay to a real DataHub deployment through:

- asset search
- metadata retrieval
- lineage retrieval
- future write-back support

The mock and live providers share the same normalized Relay data models, allowing the investigation workflow to remain unchanged regardless of the DataHub source.
